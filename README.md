# ShopRec

Рабочий MVP рекомендаций для пилотной сети небольших интернет-магазинов. Внутри магазина — похожие товары и дополнения из собственного каталога. В отдельном сценарии после покупки — дополнения партнёров из категорий, которых нет у исходного магазина.

Приложение включает сервер, SQLite, витрину, административный интерфейс, импорт каталога, настройки партнёров, встраиваемый виджет и журнал кликов. Модель доступа: **один оператор управляет пилотными магазинами**. Это не многопользовательская SaaS-платформа.

## Быстрый запуск

Нужен Python 3.10+. Внешних Python-зависимостей нет.

```bash
python3 server.py
```

Windows: дважды щёлкните `START_WINDOWS.bat` или выполните `py -3 server.py`. Linux/macOS: `./start.sh`.

- Витрина: http://127.0.0.1:8787
- Управление: http://127.0.0.1:8787/admin
- Проверка сервера: http://127.0.0.1:8787/api/health

При первом запуске создаются `data/shoprec.db` и `data/admin-token`. Откройте файл `data/admin-token` у себя и введите его содержимое в форме входа. Токен не выводится в логи и не передаётся в URL; запросы управления используют `Authorization: Bearer …`. Интерфейс хранит введённый токен только в `sessionStorage` до выхода/закрытия сессии браузера.

Альтернатива — задать случайный `SHOPREC_ADMIN_TOKEN` длиной от 24 символов в окружении. Для прослушивания вне localhost он обязателен. Файл `.env` автоматически читает Docker Compose; Python напрямую читает переменные окружения, а не `.env`.

## Docker

```bash
cp .env.example .env
# Впишите в .env свой случайный SHOPREC_ADMIN_TOKEN.
docker compose up --build -d
```

Генерация токена на вашей машине:

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(32))"
```

Контейнер работает от непривилегированного пользователя. Порт по умолчанию привязан к `127.0.0.1:8787`, база находится в именованном томе `shoprec_data` и сохраняется при пересоздании контейнера. `docker compose down` сохраняет том; опция `-v` удаляет его вместе с данными. Для удалённого пилота нужен HTTPS reverse proxy; при необходимости задайте `SHOPREC_PUBLIC_ORIGIN` в `.env`.

## Что работает

- SQLite хранит магазины, каталоги, настройки участия и события между перезапусками.
- Первый запуск создаёт 3 демонстрационных магазина и 30 вымышленных товаров. Начальные счётчики кликов равны нулю; готовых результатов, выручки и конверсий нет.
- Импорт CSV/JSON атомарно заменяет каталог **только выбранного магазина**. Другие магазины и история кликов сохраняются.
- Похожие товары ранжируются по TF-IDF и косинусному сходству названий, описаний и тегов. Тип товара должен совпадать; товар должен быть в наличии.
- Дополнения используют явные правила сочетания типов и текстовое сходство. Для ламп проверяется цоколь, для воронок и фильтров — размер.
- Собственные рекомендации всегда остаются внутри магазина.
- Партнёрские товары показываются при включённом участии обеих сторон и взаимном разрешении в списках партнёров. Исходящий блок ограничивается выбранными категориями.
- Все категории и типы, уже представленные у своего магазина, исключаются из партнёрского блока, даже если товары временно закончились.
- Клики действительно записываются на сервер. Демонстрационные и обычные события считаются раздельно; повтор с тем же UUID не увеличивает счётчик.

## Показ продукта

1. Откройте витрину «ДОМА», выберите гейзерную кофеварку Forma. В «Похожих» будут две доступные альтернативы этого магазина.
2. Переключите на дополнения собственного магазина: появятся чашки.
3. Откройте демонстрацию сценария после покупки: появятся кофе, кофемолка и весы партнёров, которых нет в ассортименте «ДОМА». Это симуляция размещения после заказа, а не проведение платежа.
4. Войдите в `/admin`, отключите одного партнёра или ограничьте категории. Вернитесь на витрину: результат изменится по сохранённым правилам.
5. Нажмите на рекомендацию. В отчёте появится соответствующий демонстрационный клик; обычные показатели не увеличатся.
6. Импортируйте новый каталог выбранного магазина, перезапустите сервер и убедитесь, что данные сохранились.

## Формат каталога

От 2 до 500 товаров **на магазин**, JSON-массив или CSV с заголовками; тело запроса до 2 МБ. Необходимые поля: `id`, `name`, `type`, `category`, `description`, `price`. Дополнительно: `tags`, `in_stock`, `color`, `compatibility`, `url`.

```json
[
  {"id":"myshop-lamp-1","name":"Лампа 1","type":"lamp","category":"Лампы","description":"Настольная лампа для чтения","price":2500,"tags":["свет","чтение"],"in_stock":true,"compatibility":"E27","color":"#D1C6B3","url":"https://store.example/products/lamp-1"},
  {"id":"myshop-lamp-2","name":"Лампа 2","type":"lamp","category":"Лампы","description":"Настольная лампа для дома","price":3100,"tags":["свет"],"in_stock":true,"compatibility":"E27","color":"#A8B49F"}
]
```

В CSV теги разделяются `|`, `in_stock` задаётся как `true`/`false`. ID уникальны во всей сети: используйте префикс магазина. Конфликт с ID другого магазина отклоняет весь импорт. `store_id` из файла не даёт перенести товар: владельца задаёт выбранный магазин запроса.

`url` — настоящая страница товара, только `http://` или `https://`, без встроенных логина/пароля. Подставьте адрес своего магазина вместо демонстрационного `.example`. В виджете нажатие откроет этот URL в новой вкладке с `noopener,noreferrer`. Без URL карточка остаётся демонстрационной и её клики принудительно попадают в `demo_*`.

Категория — узкая группа («Чашки», «Кофемолки», «Лампочки»), а не общий раздел «Дом». Для нового `type` поиск похожих работает сразу; правила дополнений добавляются в `PAIRS` в `recommender.py`. Совместимость произвольных реальных товаров требует проверки владельцем каталога.

## Настройки партнёров

`participating` включает участие магазина. `partner_allowlist` содержит разрешённые ID партнёров; разрешение должно быть взаимным. `category_allowlist` ограничивает категории товаров, показываемых в исходящем партнёрском блоке.

- `null` — все допустимые партнёры/категории.
- `[]` — ни одного.
- Массив значений — только выбранные.

Настройки не обходят ограничения наличия, совместимости и собственного ассортимента. Переименование категорий при импорте может потребовать обновить сохранённый список разрешённых категорий.

## Виджет

После размещения сервера и импорта каталога вставьте на страницу товара:

```html
<script src="https://YOUR-SHOPREC-HOST/embed.js" data-product="myshop-lamp-1"></script>
```

`data-product` должен существовать в каталоге. Виджет изолирован iframe и по умолчанию показывает собственные рекомендации магазина. `data-mode="complementary"` сразу включает дополнения. Для публичной интеграции используйте HTTPS. «Одна строка» относится к вставке блока после подготовки каталога и хостинга.

Отдельный партнёрский блок, который магазин вставляет **только на страницу завершённого заказа**:

```html
<script src="https://YOUR-SHOPREC-HOST/embed.js" data-product="myshop-lamp-1" data-mode="partner"></script>
```

Он запрашивает `/api/partners` и ведёт на `url` товара другого магазина. Размещение после заказа контролирует интеграция магазина: сам ShopRec пока не проверяет оплату или заказ. В текущей версии нет готовых CMS-коннекторов и интеграции с реальными заказами.

## API

Публичные чтения:

| Метод | Путь | Результат |
|---|---|---|
| GET | `/api/health` | статус и версия, без секретов |
| GET | `/api/session` | `authenticated` для переданного bearer |
| GET | `/api/stores` | магазины и правила сети |
| GET | `/api/products?store_id=doma` | каталог; параметр необязателен |
| GET | `/api/recommendations?product_id=moka-01&mode=similar&limit=3` | режим `similar` или `complementary` |
| GET | `/api/partners?product_id=moka-01&limit=3` | партнёрские дополнения |

Операции управления требуют bearer:

- `POST /api/stores`: `{id,name,description,participating?}`.
- `POST /api/settings`: `{store_id,participating?,partner_allowlist?,category_allowlist?}`.
- `POST /api/import`: `{store_id,format:"json",data:[...]}` либо `{store_id,format:"csv",data:"..."}`.
- `GET /api/analytics?store_id=doma`: агрегаты и последние события; без параметра — вся сеть.

Запись клика: `POST /api/events` с `{event_id,source_product_id,target_product_id,placement,is_demo}`. `event_id` — UUID; `placement` — `similar`, `complementary` или `partner`; `is_demo` по умолчанию `true`. Сервер проверяет существование товаров, актуальную доступность рекомендации, размещение, UUID и лимит запросов. Идентификаторы не превращаются в клики автоматически: событие должен отправить обработчик реального нажатия.

`internal_clicks`, `inbound_clicks`, `outbound_clicks` учитывают только `is_demo=false` для товаров с внешним URL; `demo_*` — отдельно. Витрина и виджет с настоящим URL открывают страницу и отправляют обычный клик, без URL — демонстрационный. У всех исходных вымышленных товаров URL отсутствует. Сервер не позволяет записать карточку без URL в обычный трафик. Входящий и исходящий счётчики описывают две стороны одного партнёрского перехода, их нельзя складывать как независимые переходы. События клиента могут быть подделаны: это журнал кликов MVP, не биллинг, не подтверждение загрузки внешней страницы/покупки и не антифрод-отчёт. Личные данные покупателей не собираются.

## Проверки

```bash
python3 -m unittest discover -s tests -v
node tests/test_frontend.cjs
```

Вторая команда проверяет связку интерфейса и API без браузера; для неё нужен Node.js. Приложению Node.js не требуется. Эти же проверки запускаются в GitHub Actions.

Проверяются алгоритм, совместимость, защита собственного ассортимента, взаимные списки партнёров, категории, SQLite persistence, атомарность импорта, коллизии ID, каталоги сети больше 500 товаров, авторизация, HTTP-маршруты, обход путей, размер запроса, допустимость кликов, дедупликация и раздельные счётчики демо/обычных событий. HTTP-обработчики тестируются с настоящей временной SQLite через буферы, без сетевого сокета.

На машине подготовки сетевые сокеты и запуск Chromium запрещены песочницей; здесь не выполнены живой HTTP-прогон, браузерный просмотр и сборка контейнера. Код и тесты доступны для повторной проверки в обычной среде. Docker требует загрузки базового образа; само приложение не обращается к сторонним сервисам.

## Границы MVP

Один доверенный оператор, единый admin token, синхронный TF-IDF при запросе и стандартный Python HTTP-сервер подходят для ограниченного пилота. Пока нет отдельных аккаунтов магазинов, оплаты, атрибуции заказов, подтверждения факта покупки на сервере магазина, реального обмена трафиком, автоматических фидов и production SLA. Перед внешним запуском нужны HTTPS, резервные копии SQLite, интеграция с магазином и проверка качества каталога. Партнёрский endpoint не доказывает, что заказ завершён: это должно обеспечиваться интеграцией магазина.

`data/`, `.env`, базы, токены и ключи исключены из Git и Docker build context. Секреты не нужны ни в исходниках, ни в репозитории. SVG-иллюстрации оригинальные; внешних шрифтов, фотографий и трекеров нет.
